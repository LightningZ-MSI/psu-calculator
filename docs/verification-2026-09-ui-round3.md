## 一、标志：从「手画近似」改成「官方图形本体」

### 问题

上一轮的那个「之眼」是我凭印象画的：六边形外框 + 三角形瞳孔，套在一个红色色板里。
对照官方 logo 一看就差得很远 —— **一个形状复杂的商标不可能靠手描描准**。

### 做法

新增 `tools/build-logo.mjs`，直接从官方 logo 图里把图形抠出来。工具链只用本地已有的
Edge（headless + canvas），不装任何依赖：

| 步骤 | 说明 |
|---|---|
| 1 | 把源图以 data URI 内联进探针页（data URI 同源，canvas 不会被污染，因此能读像素） |
| 2 | 读 alpha 通道。官方图本身带透明通道（纵向锁定版 90.2% 的像素是透明的），所以直接用 A 通道最准；若换成不透明的白底图，自动退回「红墨覆盖度 α = 255 − G」的算法 |
| 3 | **行投影**找出所有墨带，再按最大空白带切开图形与字标 |
| 4 | 各自裁到外接框，双线性重采样后重着色为 `#ff0033` |
| 5 | 输出 `assets/rog-eye.png` + `assets/rog-wordmark.png`；另生成自包含的 `favicon.svg`（内嵌 72×37 PNG） |
| 6 | 把 404 页的图标与两张图填成 data URI |

**为什么页面上用 CSS `mask` 而不是 `<img>`**：mask 只取 alpha 通道，颜色由
`background: var(--rog)` 提供，所以深浅主题切换 `--rog` 时标志自动跟着换
（浅色主题把 ROG 红压深到 `#d40029`），不需要维护两套图。

**为什么去掉底衬色板**：官方锁定版是**裸标志**，没有色块底衬。
「圆角/六边形色块里放一个白色 glyph」是模板站和 AI 生成页的典型做法，
去掉底衬这一步本身就在减 AI 味。

## 一之补充：改用完整锁定版（图形 + 字标）

用户随后明确「logo 用这个」并给了**纵向锁定版原图**（图形在上、两行
`REPUBLIC OF GAMERS` 字标在下）。于是把提取逻辑从「切掉字标只留图形」
改成「**把图形与字标分别切出来，都做成交付资产**」。

### 切分依据（实测）

```
SRC=2207x1900
BANDS=3   388-1101    1244-1387   1407-1511
          ↑ 图形      ↑ REPUBLIC OF  ↑ GAMERS
WIDEST_GAP=142px @y=1173
```

三条墨带、最大空白带 142px 正好落在「图形 ↔ 字标」之间，切分点自动取该空白带正中。
两行字标作为**一张图**输出（保留它们相互居中的位置关系），而不是拆成两行。

产物：

| 资产 | 尺寸 | 用途 |
|---|---|---|
| `assets/rog-eye.png` | 256×132 | 顶栏、弹窗头部、分享卡片（mask 上色） |
| `assets/rog-wordmark.png` | 340×71 | 同上，横向锁定版的字标部分 |

### 排布：为什么顶栏用横向、404 用纵向

官方纵向锁定版（图形在上、字标在下）塞进横向顶栏会把产品名挤到换行，
而且字标会被压得更小。所以：

- **顶栏 / 弹窗 / 分享卡片**：横向锁定版（图形在左、字标在右）——
  这正是官方「横向锁定版」的排法，ROG 官方本身就同时提供两种排布
- **404 页**：空间充足，用**纵向**锁定版，与用户给的原图完全一致

### 字标的最小尺寸（这是本次唯一的视觉取舍）

字标是细笔画定制字形。实测缩到 100px 宽以下就糊成一团，所以顶栏给到 **140px**
（两行各约 9px 高）。代价是 logo 块变宽，因此**窄屏（≤640px）直接隐藏字标只留图形** ——
顶栏里真正需要被读到的是「这是什么工具」，而不是品牌字标。
`browsertest` 断言顶栏字标宽度 ≥120px，防止后续有人把它调小到不可读。

## 二、UI 语言：逐条对照真实奥创界面对齐

对照三张真实截图，逐项修正：

| 项 | 之前 | 现在（依据） |
|---|---|---|
| **分区标记** | 两条斜杠 `>>`（`115deg` 两个渐变条） | **三条 `///`**。截图里 Aura Sync 的 Basic Effects / Advanced Effects、Home 的 Systems Monitor / Devices / Operating Mode 用的都是三条等距细斜杠。两条会读成「快进符号」，是另一个语义 |
| **选中态** | 只有红色描边 + 红色文字 | **极淡同色底 `rgba(255,0,51,.06)` + 红色描边 + 底部斜切条**。截图里 Aura Effects 标签页与 Home 的 Turbo 模式按钮都是「浅底 + 红下边」 |
| **面板形态** | 答案筹码六边斜切、弹窗左上右下斜切 | **干净矩形**。真实界面里所有面板都不切角 |
| **斜切的作用范围** | 容器切角 + 到处贴指示条 | **只留在分区标记与选中/关键指示条上** |
| **logo 底衬** | 红色六边色板 + 白色图形 | 裸标志（见上一节） |
| **引导卡序号** | `<span class="idx">?</span>`，与前面的 `///` 挤成「/// ? 使用方法」 | 去掉。这一栏不是「第几步」而是说明 |
| **弹窗小标题** | 五段各一根斜切短棒 | 去掉。同一枚 motif 在弹窗里重复五遍 |
| **三档电源角色标签** | 三根斜切短棒（首档红、其余灰） | 去掉。三档是**等权备选**，给其中一档加标记会误导成「就买这个」 |

### 关于「斜切」的取舍

上一轮的需求是「UI 整体带有 ROG 斜切文化」，本轮需求是「参考后三张 + 没那么 AI 味」。
两者不矛盾：**斜切在真实 ROG 界面里的落点就是「分区标记」和「选中指示条」，
不是「给每个容器切一刀」。** 所以这一轮不是删掉斜切，而是把它收回到官方界面实际使用的两个位置。

两条硬约束保留：

1. **斜切只切形状，不切文字** —— 全站零 `transform: skew` 落在文本上。
2. **不对可聚焦元素本身用 `clip-path`** —— 那会连 `:focus-visible` 的焦点环一起裁掉。
   （404 页的主按钮之前就踩了这个坑，本轮一并修掉。）

## 三、踩到的一个隐蔽 bug：样式表被静默截断

改 404 页时出现：**icon 变成一块实心红矩形，主按钮掉回浏览器默认的蓝色下划线链接。**
页面不报任何错。

排查结论：

- 浏览器解析出来的 CSS 规则只有 4 条（应为 11 条），`.eye` 之后的规则全部消失。
- `<style>` 的文本内容**完整**（6265 字符，末尾的 `.hint` 规则还在），所以不是 HTML 截断。
- 是 CSS 解析器在 `.eye` 规则处进入了不可恢复状态，把后面的规则全吞了。

**这种失败最阴的地方是它不报错**：如果不是「标志变成红块 + 按钮变蓝」这么显眼，
一条位于样式表末尾的规则被吞掉完全可以一直不被发现。

处理：

1. 404 页改用 `<img>` 承载标志 —— 这个页面刻意只用最保守的 CSS，
   少一层「mask 能不能解析 / 能不能加载」的不确定性，`alt` 顺带充当无障碍名称。
2. **新增一段常驻检查**（`browsertest.mjs`「品牌标志与样式表完整性」7 条）：
   - 首页解析出的规则数必须 ≥ 200（当前 230）；
   - 位于文件尾部的规则必须仍然生效（弹窗遮罩 `fixed`、toast `fixed`、`@media print` 存在）；
   - ROG 之眼的 mask 必须真的生效（不是 `none`，`background` 不是透明）；
   - mask 引用的图形文件必须能被取到（用 `Image` 主动探一次，因为 mask 加载失败不抛错）；
   - 404 页的之眼图片必须真的加载成功（`naturalWidth > 0`）、按钮样式生效、规则数 ≥ 11。

3. 顺带验证了**单文件产物没有同类问题**：`build-standalone.mjs` 会把 CSS 里的
   `url(rog-eye.png)` 改写成 data URI，token 形态变了。实测开发态与单文件产物
   **都解析出 230 条规则**，mask 在两边都正确解析（开发态指向 `file://` 路径，
   单文件指向 data URI），`@media print` 都存在。

## 四、本轮另外修掉的问题

| 问题 | 说明 |
|---|---|
| **`swapAttr` 把三处替换写成了「同一基准串并行」** | 三处替换都基于同一个原始串计算，再逐份赋回 `h404` —— 结果只有最后一份生效，favicon 与图形两处被静默丢弃。改成在**当前结果上依次**替换后正常。这是**我自己刚写的新代码里的 bug**，靠新加的「src 必须是完整 data URI」自检当场抓到 |
| **裸 base64 塞进 `<img src>`** | `uriOf()` 原本返回去掉 `data:` 前缀的纯 base64（那是给 favicon 里内嵌 `<image href>` 用的），却被 404 的 `src` 复用。浏览器**不报错**，只显示 alt 文字。现已拆成 `b64Of` / `uriOf` 两个函数，并在工具末尾加自检：把生成的 `src` 解回 PNG 验签名 |
| **404 页按「数据形状」定位替换 → 坏的修不回来** | 原来用 `src="(?:__ROG_EYE_URI__|data:image/png;base64,[^"]*)"` 匹配。一旦上一次跑出坏结果（裸 base64），正则就匹配不上，工具既修不好、也不会报错地留下坏文件。改成按**元素身份**（`class="eye"` / `class="wordmark"` / `rel="icon"`）定位，可自我修复 |
| **404 页的图标路径在项目子路径站点上是错的** | 原来是 `href="/favicon.svg"`。本站在 GitHub Pages 上是项目子路径站点（`https://<user>.github.io/-/`），根绝对的 `/favicon.svg` 会解析到域名根。而 404 是「按出错地址渲染、浏览器 URL 不变」的页面，相对路径又会跟着出错地址的深度乱跑 —— 所以 404 页的图标与标志全部改成内联 data URI，做到真正自包含 |
| **`dbDate` 一直是空引用** | 新增的 DOM id 对账检查（86 个 id）抓到 `app.js` 引用了 HTML 里不存在的 `dbDate`，被 `if (d)` 静默兜住 —— 也就是说「数据截止日期」在某次改版中从界面上消失了。已加回顶栏 |
| **404 页主按钮被 `clip-path` 裁掉焦点环** | 该按钮是 `<a>`，可聚焦。已改为干净矩形 |
| **`designcheck` 的渐变白名单太松** | 原来是「白名单某些 stop 百分比」，只要别处照抄一组相同 stop 值就能绕过。改为**把分区标记那条规则整段剔除后再要求零渐变**，并额外断言分区标记确实是三条 |
| **`shots.mjs` 的移动端 iframe 漏带 `?nodisclaimer=1`** | 外层包装页的参数传不进 iframe，所以第一版「移动端截图」拍到的其实是盖在弹窗上面的那一层。靠**看截图**发现 |
| **`browsertest.mjs` 的产物过期检测漏了 `js/ui.js`** | 意味着只改 `ui.js` 时不会触发「产物过期」告警，会拿旧产物做冒烟测试。已补，并把两张 logo 图也加进去 |

## 六、已知遗留

1. **`04-构建方案.md` 的 Phase 2 / Phase 3 依然没做**（数据层拆分、向导式流程），与本轮无关。
2. **样式表被截断的根因没有完全定位**。已经用二分法排除了：mask 的引号/无引号形式、
   `mask` 简写与长写、`center / contain`、data URI 的长度与内容、注释、前置规则。
   这些组合在**最小复现里全部正常**。最终的规避方式是 404 页改用 `<img>`，
   并且新增了「规则数 + 尾部规则生效」的常驻断言来兜住这一类失败。
   记录在此，以免下次遇到时重复排查。
3. **ROG 之眼与 ROG 红是华硕的注册商标**，本项目的图形素材取自华硕公开的官方 logo 图。
   本工具是第三方爱好者作品，与华硕无隶属关系；README 的「界面设计」一节已写明商标说明，
   并刻意没有搬用 "FOR THOSE WHO DARE" 这类官方标语。若要商用需先换掉标志。
4. **`apple-touch-icon` 指向 SVG**，而 iOS 的 apple-touch-icon 不认 SVG。
   `build-logo.mjs` 已能产出任意尺寸的 PNG，后续要修的话是一行的事，本轮未动。
